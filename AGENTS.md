# AGENTS

## Fast start
- Install: `pnpm install` (see "Lockfiles"). Dev: `npm run dev` (Vite on :3000). Verify: `npm run typecheck && npm run build`. Preview build: `npm run preview`.
- No `test`, `lint`, or formatter scripts. `npm run typecheck` (strict tsc) and `npm run build` (Vite + Netlify SSR) are the verification gates.

## Lockfiles
- Repo ships `bun.lock` AND `pnpm-lock.yaml`. There is NO `package-lock.json`. `node_modules` was installed by pnpm (`.modules.yaml` present). Prefer `pnpm install` to match the committed state; don't touch the other lockfile unless intentionally migrating.
- `pnpm-workspace.yaml` is not present; pnpm warns about ignored build scripts (`@parcel/watcher`, `esbuild`, `sharp`) on first install. Approve them once with `pnpm approve-builds` so native bindings compile, or just rebuild with `pnpm rebuild`.

## Architecture (TanStack Start on Vite)
- Entry is generated by the framework; no `src/main.tsx` and no `index.html` (TanStack Start renders the document shell from `src/routes/__root.tsx`).
- `src/router.tsx` — exports `getRouter()` and registers the router type for type-safe links/loaders. Pulls the route tree from the auto-generated `src/routeTree.gen.ts` (do not edit; commit it for type safety).
- `src/routes/__root.tsx` — the document shell. Owns `<html>`/`<head>`/`<body>`, the global `<HeadContent />`/`<Scripts>`, the `index.css` stylesheet (imported via `?url`), the Google Fonts `<link>`, and an `<ErrorBoundary>` wrapping `<Outlet />`. Add new `<link>`/`<meta>` entries to its `head` function, not a new `index.html`.
- `src/routes/index.tsx` — the only route so far. Imports `App` from `src/App.tsx` and uses it as the route component.

### `src/App.tsx` — orchestration
- Wires three hooks (`useSupabaseAuth`, `useLiveData`, `useToast`) plus local UI state (`settings`, `tab`, `chartMode`, `modal`, `startTime`).
- Renders the loading screen while `authChecking`, the `LoginScreen` when no session, and the dashboard otherwise (Header → top row → MiniCards → ChartPanel → StatusBar → modal → toast).
- KPIs come from `useMemo(() => computeKpis(history))`.
- All magic numbers (polling cadence, history cap, chart window, toast TTL, default settings) live in `src/lib/config.ts`.

### `src/hooks/`
- `useSupabaseAuth.ts` — `signInWithPassword`, session listener, login/logout. Returns `{ session, authChecking, authBusy, authError, login, logout }`.
- `useLiveData.ts` — initial `fetchHistory` (capped at `HISTORY_LIMIT`) + 1 Hz `setInterval` polling (`fetchLatestPoint`, `MAX_CHART_POINTS` sliding window in memory). ESP online = `(now - created_at) < ESP_ONLINE_THRESHOLD_S`. `reload()` now returns `Promise<boolean>` so the caller can react to fetch failures.
- `useToast.ts` — single global toast with auto-dismiss (`TOAST_TTL_MS`).

### `src/lib/`
- `config.ts` — `POLL_INTERVAL_MS`, `HISTORY_LIMIT`, `MAX_CHART_POINTS`, `ESP_ONLINE_THRESHOLD_S`, `MINI_CARD_COUNT`, `TOAST_TTL_MS`, `TOTAL_DUR_SECONDS`, `UNCERTAINTY`, `DEFAULTS` (initial `Settings`).
- `types.ts` — `Settings`, `DataRow`, `Kpis`, `ChartMode`, `Tab`, `ModalType`. All shared types live here.
- `stats.ts` — `computeKpis(history)` (min/max, stddev, `u_R`/`u_E`/`u_rep`, `uc`, `U=k·uc`, homogeneity, endpoint slope) and `stddev`.
- `pt100.ts` — `buildPt100FilteredMap(history)` cumulative running mean of valid PT100 values, keyed by row id. Used by `csv.ts` and `DataTable.tsx`; keep both call sites in sync.
- `csv.ts` — `buildCsvRows(history, settings)`, `downloadCsv(rows, filename)`, `defaultCsvFilename()`. The Timestamp column is a full fr-FR `toLocaleString` (date + time), not just HH:mm:ss.
- `supabase/client.ts` — `createClient` with `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` env vars, with the previously committed values as fallbacks.
- `supabase/data.ts` — `fetchHistory(limit)` (returns `HistoryFetchResult` with `rows`, `lastId`, `lastSeenTs`, `error`) and `fetchLatestPoint()`. `mapRows` reverses the id-DESC Supabase result into oldest→newest order.
- `supabase/format.ts` — `formatTS(iso)` (fr-FR HH:mm:ss only, used for in-app labels).

### `src/components/`
- `Header.tsx`, `SensorCard.tsx`, `InfoPanel.tsx`, `MiniCards.tsx`, `StatusBar.tsx`, `SettingsModal.tsx`, `LoginScreen.tsx`, `ErrorBoundary.tsx` — presentational; all driven by props from `App.tsx`.
- `chart/ChartPanel.tsx` — tab bar (`chart` / `table` / `uncert`) + mode selector (`avg` / `hum`). Routes to:
  - `chart/RealtimeChart.tsx` — Chart.js v4 Line (manually registered scales/plugins). Renders the temperature (Siemens + optional PT100 overlay) or humidity dataset based on `mode` prop. The PT100 dataset is appended only if at least one row has a non-null `pt100`.
  - `chart/DataTable.tsx` — last 40 rows with `PT100_Filtered` and ΔT columns. Reuses `buildPt100FilteredMap`.
  - `chart/UncertaintyView.tsx` — six `u-card` tiles + the formula block. Pulls constants from `UNCERTAINTY`.
  - `chart/chartOptions.ts` — `createOptions(forHum, yColor)` returns the shared ChartOptions object (twin y-axes `yT` / `yH`).
- Styling: all components lean on `src/index.css` CSS variables (`--bg`, `--cyan`, `--red`, …) + custom classes. Tailwind 4 is installed (`@tailwindcss/vite` + `@import "tailwindcss";` at the top of `index.css`) but no utility classes are used in the live tree yet.

## SSR caveat
- TanStack Start SSR is on by default. The dashboard is fundamentally client-driven (Supabase auth reads `localStorage` and the 1 Hz poll is per-session), so SSR will render the `authChecking: true` "Vérification de la session..." loading screen, and the client takes over after hydration. The `<ErrorBoundary>` inside `__root.tsx` covers `<Outlet />`. If you want fully client-side rendering, wrap the index route component in a "mounted" guard.

## Supabase data contract
- Client + URL + anon JWT live in `src/lib/supabase/client.ts`, read from `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`, with the previously committed values as fallbacks. Configure the env vars in Netlify (or a local `.env.local`, which is `.gitignore`d) to override; the anon key is safe to commit, never commit a service-role key.
- Required table `public.data` with columns used by queries: `id` (int, ordering key), `temperature` (float, "Siemens" reference), `pt100_temp` (float, nullable — overlay/filter math depends on this), `humidity` (float), `created_at` (timestamptz). `App.tsx`, `RealtimeChart.tsx`, `DataTable.tsx`, and the CSV exporter all read it.
- Initial load: `select(...).order('id', desc).limit(HISTORY_LIMIT)` where `HISTORY_LIMIT = 2000`. Polling uses `.limit(1)` on the same select every `POLL_INTERVAL_MS` (1000 ms). "ESP online" = `(now - created_at) < ESP_ONLINE_THRESHOLD_S` (10 s).
- Auth uses `signInWithPassword` (`LoginScreen`). Without a session the app renders `LoginScreen` and the polling effect short-circuits.

## CSV / upload quirks
- CSV export lives in `App.tsx#handleExport` → `lib/csv.ts`. Columns: `Timestamp,ID,Temperature,PT100,PT100_Filtered,Ecart_T,Humidite`. The "Timestamp" column is a full fr-FR date+time string built from `d.created_at` (NOT `d.label`, which is HH:mm:ss only). The "PT100 Filtered" column is a cumulative running mean of valid `pt100_temp` values, computed in `lib/pt100.ts` and reused verbatim by `DataTable.tsx` — keep `csv.ts` and `DataTable.tsx` in sync if you edit either.
- `defaultCsvFilename()` uses minute-granularity (`LEST_2026-06-05T01-06.csv`) so two exports inside the same second still get distinct files.
- The Header previously advertised a "Charger Profil" upload (`.csv`/`.xlsx`); it was a silent no-op. Button removed; if real ingestion is wanted later, treat it as a feature change.

## UI / copy conventions
- UI copy is French; keep tone and accents when editing user-visible strings.
- Emoji are used as iconography in tabs, toasts, and status text (e.g. `📊`, `✅`, `⚠️`). Match the surrounding style instead of swapping for lucide icons.
- Fonts (`DM Mono`, `Syne`) are loaded via Google Fonts in `src/routes/__root.tsx`; CSS references them through `--font-mono` / `--font-main`.
